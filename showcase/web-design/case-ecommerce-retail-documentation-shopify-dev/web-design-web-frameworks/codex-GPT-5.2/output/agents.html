Build agents with UCP

Build agentic shopping experiences powered by CommerceForge merchants — from product discovery through checkout. Universal Commerce Protocol (UCP) defines the actors, messages, and handoffs needed for reliable, secure flows.

UCP Identity Payments Observability

Protocol overview

UCP standardizes how agents request catalog context, how merchants return offers, and how checkout is handed off to payment and credential providers. 

# Example message intent (conceptual)
agent → merchant: "Find running shoes under $150"
merchant → agent: offers + availability + policies

Protocol actors

UCP defines interactions between four primary actors:

agent

Platforms, agents, and applications acting on behalf of buyers

merchant

Sellers providing products and fulfillment

CP

Credential Providers managing buyer identity and authentication

PSP

Payment Service Providers handling payment processing

How it works

Design flows around explicit handoffs: discovery → selection → identity confirmation → payment → order confirmation. Each step should be auditable, replay-safe, and resilient to partial failures.

Idempotency

Use request IDs and safely retry without duplicating orders.

Policy clarity

Return shipping + tax + returns policies as structured data, not free text.

Product discovery

Start with low-latency catalog queries, then refine with constraints (size, availability, shipping window). Cache summaries and revalidate before checkout. 

# Discovery loop
1) query catalog
2) rank + explain
3) confirm constraints
4) refresh price/stock
5) proceed to checkout

Checkout flow

Treat checkout as a secure transaction boundary: final totals, identity verification, payment authorization, and merchant confirmation. Keep human-readable receipts plus machine-verifiable payloads.

Credential step

Use CP to confirm buyer identity and consent before payment authorization.

Payment step

Use PSP for authorization + capture, then reconcile against merchant order status.
